    Configuration options¶

    Generated page

    This page is generated from the doc comments in hscontrol/types/config.go by go generate ./hscontrol/types/. Edit the comments there, not this page.

    Every key headscale reads, in the order headscale generate config prints them, with its type, default, environment variable and an example for a configuration file, the environment and NixOS. Keys that no longer work are listed under Removed keys. Configuration explains where headscale finds its configuration, how to check it, and shows the full example.

    Conventions¶

    Value types¶

    Type Format Example
    string Text. Quote it where YAML would read another type, as in "0x1F" or "null". /var/lib/headscale/db.sqlite
    boolean true or false. true
    integer A whole number. 1024
    duration A number with a unit, ms, s, m, h, d, w or y, units combined largest first; 0 needs none. 1h30m
    file mode Octal permission bits, quoted. "0770"
    listen address host:port. An empty host listens on every address; the port may be http or https. 0.0.0.0:8080
    URL An absolute http:// or https:// URL with a host. https://headscale.example.com
    prefix An IP range in CIDR notation. 100.64.0.0/10
    secret Text, or file:<path> to read it from a file. file:/run/secrets/oidc_client_secret
    enum One of the values listed with the key. sqlite
    DNS record An object with name, type and value. {name: grafana.example.com, type: A, value: 100.64.0.3}
    value Whatever the setting takes: text, a number, a boolean, a list or a map. file:/run/secrets/cloudflare
    list A list. A variable holds it as a JSON array or, unless its values are objects, separated by spaces. An empty item is an error. [9.9.9.9, 2620:fe::fe]
    map Keys you choose, each with a value. A variable holds a JSON object. {corp.example.com: [192.0.2.53]}

    Environment variables¶

    Every key can also be set with an environment variable: HEADSCALE_ and the key's path in capitals, with _ for ., e.g. HEADSCALE_LOG_LEVEL for log.level. Each key below names its variable. A variable wins over the configuration file, which wins over the default. An empty variable, like a key written with no value in the file, counts as unset and keeps the default. A variable set to "" means what "" means in the configuration file: it clears a key with a default, as prefixes.v6: "" does, and is an error where the file's "" is one. A list also clears with []. Quote the value so the quotes reach headscale:

    export HEADSCALE_PREFIXES_V6='""'
export HEADSCALE_DERP_URLS='[]'
    docker-compose.yaml
    environment:
  HEADSCALE_PREFIXES_V6: '""'
  HEADSCALE_DERP_URLS: '[]'

    An env file (a Compose env_file, a systemd EnvironmentFile=) and a systemd Environment= strip one level of quotes, so KEY="" there arrives empty and keeps the default: write KEY='""' in an env file and Environment='KEY=""' in a unit.

    A list is a JSON array or, unless its values are objects, its values separated by spaces. A map is a JSON object, which replaces the map in the configuration file instead of merging into it. The examples below write every list and map as JSON.

    A HEADSCALE_ variable that names no key logs a warning, and one for a removed key also says what to do instead. Other software uses the same prefix, so neither stops headscale.

    A DNS provider setting that takes text can also be set on its own as HEADSCALE_DNS_CHALLENGE_PROVIDER_<SETTING>, e.g. HEADSCALE_DNS_CHALLENGE_PROVIDER_API_TOKEN; see dns.challenge.provider.

    Secrets¶

    A secret takes the value itself or file:<path>, which reads it from that file. Environment variables in the path are expanded, as in file:${CREDENTIALS_DIRECTORY}/oidc_client_secret, and whitespace around the file's contents is trimmed; an empty file is an error. Headscale reads the file only where the secret is used, and headscale check config and headscale check all never read it. headscale generate config --running and /debug/config show a literal secret as <redacted> and a file: reference as written.

    The secrets are database.postgres.pass, oidc.client_secret, cli.api_key and every string setting of dns.challenge.provider.

    On NixOS, keep a secret out of the Nix store: load it as a systemd credential and point the key at it.

    services.headscale.settings.oidc.client_secret = "file:\${CREDENTIALS_DIRECTORY}/oidc_client_secret";
systemd.services.headscale.serviceConfig.LoadCredential = [ "oidc_client_secret:/run/secrets/oidc_client_secret" ];

    server_url¶

    • Type: string
    • Required
    • Env: HEADSCALE_SERVER_URL

    The URL clients connect to, with its http:// or https:// scheme, e.g. https://headscale.example.com:443. A trailing slash is trimmed on load. Its host must not be dns.base_domain or a name below it.

    server_url: https://headscale.example.com

    export HEADSCALE_SERVER_URL=https://headscale.example.com

    services.headscale.settings.server_url = "https://headscale.example.com";

    listen_addr¶

    • Type: listen address
    • Default: 0.0.0.0:8080
    • Env: HEADSCALE_LISTEN_ADDR

    The host:port the server listens on for clients, the API and the web pages. It serves HTTPS when tls.cert_path or tls.acme.hostname is set, plain HTTP otherwise. The default listens on every address, IPv4 and IPv6 alike.

    listen_addr: 127.0.0.1:8080

    export HEADSCALE_LISTEN_ADDR=127.0.0.1:8080

    services.headscale.settings.listen_addr = "127.0.0.1:8080";

    metrics_listen_addr¶

    • Type: listen address
    • Default: ""
    • Env: HEADSCALE_METRICS_LISTEN_ADDR

    The host:port serving /metrics and /debug; keep it private. Empty disables this listener.

    metrics_listen_addr: 127.0.0.1:9090

    export HEADSCALE_METRICS_LISTEN_ADDR=127.0.0.1:9090

    services.headscale.settings.metrics_listen_addr = "127.0.0.1:9090";

    unix_socket¶

    • Type: string
    • Default: /var/run/headscale/headscale.sock
    • Env: HEADSCALE_UNIX_SOCKET

    Where the server serves the API without authentication, for the CLI on the same host. The CLI connects to it when cli.address is empty.

    unix_socket: /run/headscale/headscale.sock

    export HEADSCALE_UNIX_SOCKET=/run/headscale/headscale.sock

    services.headscale.settings.unix_socket = "/run/headscale/headscale.sock";

    unix_socket_permission¶

    • Type: file mode
    • Default: "0770"
    • Env: HEADSCALE_UNIX_SOCKET_PERMISSION

    The file mode of unix_socket, in quoted octal ("0770"): unquoted, YAML reads 0770 as the number 504.

    unix_socket_permission: "0660"

    export HEADSCALE_UNIX_SOCKET_PERMISSION=0660

    services.headscale.settings.unix_socket_permission = "0660";

    trusted_proxies¶

    • Type: list of prefixes
    • Default: []
    • Env: HEADSCALE_TRUSTED_PROXIES (space-separated or JSON array)

    The CIDRs of reverse proxies whose True-Client-IP, X-Real-IP and X-Forwarded-For headers are honoured. Empty ignores those headers. Set without a proxy in front, clients can spoof their source IP in logs and the v2 API.

    trusted_proxies:
  - 192.0.2.10/32
  - 2001:db8::10/128

    export HEADSCALE_TRUSTED_PROXIES='["192.0.2.10/32","2001:db8::10/128"]'

    services.headscale.settings.trusted_proxies = [
  "192.0.2.10/32"
  "2001:db8::10/128"
];

    node.expiry¶

    • Type: duration
    • Default: 0s
    • Env: HEADSCALE_NODE_EXPIRY

    The key expiry given to a non-tagged node that registers without one, whatever the method (auth key, CLI, web, OIDC).     Replaces oidc.expiry (removed).

    Covers ephemeral nodes, which register with an ephemeral auth key and are deleted once they have been offline for node.ephemeral.inactivity_timeout.

    node.routes¶

    Covers the routes nodes advertise. See Routes.

    All node.routes keys and defaults 
    node:
  routes:
    ha:
      probe_interval: 10s
      probe_timeout: 5s

    node.routes.ha¶

    Health probing of HA subnet routers. When two or more nodes advertise the same route, headscale pings each over Noise and moves the route away from one that does not answer in time. See High availability.

    All node.routes.ha keys and defaults 
    node:
  routes:
    ha:
      probe_interval: 10s
      probe_timeout: 5s
    node.routes.ha.probe_interval¶
    • Type: duration
    • Default: 10s
    • Env: HEADSCALE_NODE_ROUTES_HA_PROBE_INTERVAL

    How often HA subnet routers are probed; a positive interval must be at least 2s. Zero or negative disables probing, and with it the node.routes.ha.probe_timeout rules.

    node:
  routes:
    ha:
      probe_interval: 30s

    export HEADSCALE_NODE_ROUTES_HA_PROBE_INTERVAL=30s

    services.headscale.settings.node.routes.ha.probe_interval = "30s";
    node.routes.ha.probe_timeout¶
    • Type: duration
    • Default: 5s
    • Env: HEADSCALE_NODE_ROUTES_HA_PROBE_TIMEOUT

    The maximum time to wait for a probe response before declaring a node unhealthy; at least 1s and less than node.routes.ha.probe_interval.

    node:
  routes:
    ha:
      probe_timeout: 3s

    export HEADSCALE_NODE_ROUTES_HA_PROBE_TIMEOUT=3s

    services.headscale.settings.node.routes.ha.probe_timeout = "3s";

    The servers asked for the zone's nameservers, each an IP or host with an optional port (53 if omitted). Empty uses the default public resolvers. The system resolver is never used: on a host running MagicDNS it answers for dns.base_domain itself.

    dns:
  challenge:
    resolvers:
      - 9.9.9.9:53
      - '[2620:fe::fe]:53'

    export HEADSCALE_DNS_CHALLENGE_RESOLVERS='["9.9.9.9:53","[2620:fe::fe]:53"]'

    services.headscale.settings.dns.challenge.resolvers = [
  "9.9.9.9:53"
  "[2620:fe::fe]:53"
];

    dns.challenge.provider¶

    • Type: map of <setting> → value
    • Default: {}
    • Env: HEADSCALE_DNS_CHALLENGE_PROVIDER (JSON object)

    The DNS provider that writes challenge records: name selects it, the other keys are its settings. Keys are lowercased on load, at every depth; two that differ only in case are an error. A string setting may be file:<path> to read it from a file. headscale generate config --running and /debug/config show name and file: references; every other setting is <redacted>, as any may be a credential. See DNS-01 challenge provider to set a provider up, acme-dns included, and to set it from environment variables.

    Provider Settings
    acmedns config, password, server_url, subdomain, username
    cloudflare api_token, zone_token
    gigahost api_key
    hetzner api_token
    powerdns api_token, debug, server_id, server_url
    rfc2136 key, key_alg, key_name, server

    Each text setting can also be set on its own as HEADSCALE_DNS_CHALLENGE_PROVIDER_<SETTING>, e.g. HEADSCALE_DNS_CHALLENGE_PROVIDER_API_TOKEN, which wins over the same setting in HEADSCALE_DNS_CHALLENGE_PROVIDER and in the configuration file. An object setting, such as the config of acmedns, goes inside the JSON object of HEADSCALE_DNS_CHALLENGE_PROVIDER; see Environment variables.

    dns:
  challenge:
    provider:
      api_token: file:/run/secrets/cloudflare
      name: cloudflare

    export HEADSCALE_DNS_CHALLENGE_PROVIDER='{"api_token":"file:/run/secrets/cloudflare","name":"cloudflare"}'

    services.headscale.settings.dns.challenge.provider = {
  api_token = "file:\${CREDENTIALS_DIRECTORY}/dns_challenge_provider_api_token";
  name = "cloudflare";
};
systemd.services.headscale.serviceConfig.LoadCredential = [ "dns_challenge_provider_api_token:/run/secrets/cloudflare" ];
