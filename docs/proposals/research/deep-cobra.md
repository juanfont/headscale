# Deep research: spf13/cobra + spf13/pflag as parser and completer only

Date: 2026-11-17. Phase A (desk research + probes). Phase B (adapter on `spikes/kit`) pending.

Versions under test: `github.com/spf13/cobra v1.10.2` (2025-12-04) with `github.com/spf13/pflag v1.1.0`
(tag 2026-10-29, release 2026-11-06), Go 1.27.3 from `nix develop`.

Evidence:

- Probe module: `spikes/probe-cobra/` (`adapter.go` 376 lines incl. demo specs and `main`, of which
  ~190 non-comment lines are the reusable adapter; `probe_test.go` 50 cases + 200 parallel fresh-tree
  runs + completion cases). `CGO_ENABLED=1 go test -race -count=1 ./...` passes.
- Real shells driven against the probe binary: bash 5.3 + bash-completion 2.17 (calls
  `__start_headscale` with `COMP_WORDS`), fish 4.9.3 (`complete -C`), zsh 5.9.1 (zpty, Tab on a live
  line). Scripts in scratch: `headscale completion {bash,zsh,fish,powershell}` from the probe.
- Sources read: `spikes/src/cobra` (main = adbc881, 7 commits after v1.10.2), `spikes/src/pflag`
  (master 44b0d47), `spikes/src/cobra-v1.10.2-pflag110` (v1.10.2 + pflag 1.1.0, for the test run).

## Verdict in one paragraph

Cobra can be cut down to parser + completer, and everything 001 and DECISIONS.md ask for is
reachable — but about a quarter of it only through workarounds that rely on cobra internals
(`Find`'s flag-skipping heuristic, an empty-named help command, group commands made runnable,
completion's double parse). Typed flag errors are real (pflag ≥ 1.0.7). Completion is the best of
any candidate and works in bash, zsh and fish, including comma lists. The cost is not capability,
it is that each workaround is a place where a cobra patch release can change behaviour, and the
project merges ~10 PRs a year with one active merger, so bugs we hit (several are open with PRs)
wait. Staying on cobra is zero migration cost for users and nixpkgs.

Trap found by the probe: a **bool leaf flag before the subcommand** (`headscale --force nodes delete 12`).
`Find` cannot know `--force` is a bool at the root, assumes it takes a value (`stripFlags`,
command.go:691), swallows `nodes`, and our root handler sees an unknown command `nodes`. Our group
handler can detect "the word is a known child" and report "unknown flag --force" instead (~5 lines).
Only `-c`/`-o`/`-h` are meant to be used there, and those are known at the root, so this is wording only.

## 2. Completion (D1, D2)

How it works: the scripts are generic per program name; at every Tab the shell runs
`headscale __complete <words…>` and the binary prints candidates (`value\tdescription`) and a final
`:<directive>` line. The scripts never change when the tree changes, so nixpkgs' build-time
`headscale completion bash|fish|zsh` keeps working.

D1 proof: in every completion case the leaf `RunE` was never reached (TestComplete asserts it).
`__complete` itself is a cobra command, so `execute` runs `initializers` and the root's
`PersistentPreRun(E)` for it (command.go:959, 984-998); we register neither, so no config and no
network by construction. Our builder's config load lives in the leaf callback.

## 3. Errors (D4)

- Unknown flag: `*pflag.NotExistError` → `GetSpecifiedName()` (`force`, `r`) and
  `GetSpecifiedShortnames()` (`r` in `-xr`). Path: the `*cobra.Command` returned by `ExecuteContextC`.
- Missing value: `*pflag.ValueRequiredError` → `GetFlag().Name`.
- Bad value (only for typed pflag kinds, which we do not use): `*pflag.InvalidValueError`.
- `---x`, `--=x`: `*pflag.InvalidSyntaxError`.
- Unknown command: no type in cobra, only `fmt.Errorf` strings. Solved by never letting cobra
  produce it (group `RunE` + `Args` set), so our layer gets `{Path, Word}` without text parsing.
  Running `Find` or `Traverse` ourselves is not needed: `Find` returns the deepest group and the
  remaining args, which is exactly what the group `RunE` receives.
- Typed errors exist since pflag v1.0.7 (2025-07-16, commits 8d77158, ca5cf96). Headscale today
  pins pflag v1.0.10, so they are already available; v1.1.0 is not needed for D4.

## 4. Staying out of the way

See the table at the end of §1. Summary: everything can be silenced except the `help` command
(workaround) and five env vars read on the completion path. Package-level state cobra still holds:
`flagCompletionFunctions` (grows per fresh tree), `initializers`/`finalizers`, five mutable
`Enable*`/`Mousetrap*` vars, template funcs.

## 5. D3 with the twist

Three designs were probed:

| Design                                                                                                                                            | `-c x nodes list` | `check config -o json` refused                                                           | `-c x nodes li<Tab>`                                                                                                        | Cost                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| A. `-o/-c` local on root, every group, and leaves that take them                                                                                  | works             | yes, natively (`NotExistError` for `o` on the leaf)                                      | **broken**: cobra skips subcommand completion when a local non-persistent flag is set on the group (completions.go:503-516) | 0 extra lines, broken completion |
| B. `-o/-c` persistent on root (today's headscale), leaf checks                                                                                    | works             | only by our check                                                                        | works, but `check config --<Tab>` offers `--output`                                                                         | 3 lines                          |
| **C. B with the root flags hidden + visible local `-o/-c` on leaves that take them** (local shadows inherited: `AddFlagSet` skips existing names) | works             | our check: inherited flag `Changed` and not in `LocalFlags()` → our "unknown flag" error | works, and `check config --<Tab>` shows only `--config --help`                                                              | 6 lines                          |

C is in the probe (`Build` + leaf `RunE`). Without hidden persistent flags `Find` still steps over
`-o json` before the subcommand because it assumes an unknown flag takes a value, but that is the
same heuristic that produces the bool trap; C keeps it exact for `-o`/`-c`.

`TraverseChildren` was rejected: it parses parent-level flags into the parent's flag set, so the
leaf never sees `-c x`, the adapter must merge parents, and open PRs show its `--` handling is
buggy ([#2555](https://github.com/spf13/cobra/pull/2555), [#2574](https://github.com/spf13/cobra/pull/2574), [#2510](https://github.com/spf13/cobra/pull/2510)).

## 8. Migration

Staying on cobra, behind the adapter:

- User typing the same commands: no framework-caused change. Flag grammar is pflag's today and
  tomorrow (`-ojson`, `--x=false`, interspersed, `--`). Changes come from 001 itself (`check config -o json` becomes an error because `-o` stops being inherited; `headscale help` stops existing by
  D8; `nodes bogus` becomes an error instead of help + exit 0).
- nixpkgs: `headscale completion bash|fish|zsh` keeps working and the script bytes stay the same
  when our `completion <shell>` leaf calls the generators the default command calls. Today's
  `--no-descriptions` flag on those subcommands goes away (nixpkgs does not pass it).
- 128 integration calls: change because of the redesign only; nothing because of the framework.

## Three strongest reasons for

1. **Completion is done and proven** in bash, zsh and fish (and generated for PowerShell), binary
   answered (D1), with descriptions, per-flag values, comma lists and file filters; nixpkgs' call and
   script bytes stay as they are. No other finalist has this without our own code.
1. **Zero user-visible migration**: pflag grammar is today's grammar; the only changes are the ones
   001 makes on purpose.
1. **Typed flag errors and the "given" bit are native**, and the remaining gaps (unknown command,
   given twice, `--version`) are small, testable code in the one adapter file.

## Three strongest reasons against

1. **The cut-down relies on internals**: `Find`'s value-skipping heuristic (bool trap), the
   empty-named help command, runnable groups to beat `legacyArgs`/ErrHelp, `PassUnknownFlagToArgs`
   on groups, the `__complete` argv rewrite, a counting Value because completion parses twice. Each
   is behaviour no API promises; a fix like #2529 or #2535 would change some of it.
1. **Slow upstream with one active merger**: bugs that hit us have open PRs that wait; last release
   11.5 months ago; cobra's own test suite does not pass with the current pflag.
1. **Two masters**: cobra lags pflag; pflag is now the active one and changes text (and had a
   regression within days). Our layer owns text, so only behaviour matters, but we track two
   modules whose maintainers do not move together.

## What will hurt in two years

- A cobra release that merges #2529/#2535/#2574-style fixes changes `Find`/completion behaviour the
  adapter leans on; the probe's tests must live on as adapter tests (they are cheap).
- If cobra stays frozen, the dash-value completion rewrite, the help-command workaround and the
  given-twice counter are permanent local patches.
- `flagCompletionFunctions` leaks per fresh tree in a long test binary (thousands of cases × flags):
  small, but real.

## Open questions for the maintainer

1. **D8 vs cobra's mandatory `help` command.**
   (a) Keep the empty-named hidden help command (1 line; relies on `Find` never matching `""` and on
   shells dropping an empty candidate — bash and fish checked, zsh not).
   (b) Name it `help`, hidden, and have it return our unknown-command error with a "use --help"
   hint from the D5 table (5 lines; `help` shows up in root Tab completion because cobra lists the
   help command even when hidden).
1. **Dash-leading values in completion (`--sort -last<Tab>`).**
   (a) Ship the ~25-line argv rewrite in the adapter (works in all three shells, tested here).
   (b) Accept it: document `--sort=-last-seen` for completion, and set the flag's default directive
   to `NoFileComp` so the shell at least does not offer file names (0 lines, worse UX).
1. **Which pflag.**
   (a) pflag v1.1.0 with cobra v1.10.2 (needed for `PassUnknownFlagToArgs`; cobra's own tests do not
   pass with it, text only; gh runs it).
   (b) Stay on v1.0.10 and use `IgnoreUnknownFlag` on groups (removed commands still get "unknown
   command"; `nodes --bogus` would show help instead of an unknown-flag error unless the group
   handler re-checks raw argv, ~10 lines).
1. **Bool flag before the subcommand (`headscale --force nodes delete 12`).**
   (a) Detect "word is a known child" in the group handler and report the flag (~5 lines).
   (b) Leave cobra's result ("unknown command nodes"); only odd input hits it.
1. **Hedge against upstream stalling.**
   (a) Nothing now; the adapter is the only importer, and the probe tests become adapter tests.
   (b) Vendor cobra's four scripts and write our own `__complete` responder (Tailscale pattern,
   ~200 lines + script re-sync by hand), which frees the parser choice later.

Not checked: zsh behaviour with the empty help candidate; PowerShell run; carapace/fang beyond
their entry functions; binary size with pflag 1.1.0 (expected same order as 1.0.10).

program name; nothing to keep current beyond the cobra version. They do not depend on the tree,
so nixpkgs' build-time generation stays valid.

### What surprised me

- Everything MUST passed on the first run; the Phase A probe had already found the traps.
- `Exec` refusing an inherited global made D3 free: the hidden persistent `-o/-c` design needs

- The empty-named help command and the empty candidate line it adds to every root `__complete`.
- Runnable groups plus `PassUnknownFlagToArgs` plus splitting the args again: three pieces to make

- Parsing `__complete`'s text protocol back in `Complete` to satisfy an in-process API, when the

### Did Phase B change the Phase A verdict?

No. It confirmed it: capability is complete (112/112, 4/4 stretch, all four shells), and the cost
sits in ~30 lines that work around cobra rather than use it, plus ~20 more of API used against
its grain. One more upstream bug (fish) joins the list of things that would wait for a release.

### Five years of this adapter

What would worry me is not cobra disappearing but cobra moving slowly and then suddenly: the
adapter leans on behaviour no API promises (`Find`'s guess that an unknown flag takes a value,
completion listing the help command, the order "parse, help flag, runnable, args, run", the
double parse in `__complete`, the fish and bash script details), and the open PRs that would fix
our bugs (#2529, #2535, #2459, #2574) also change exactly that behaviour, landing in one release
after a year of nothing, reviewed by one person. pflag moves faster than cobra and changes text
and edge cases (v1.1.0 regression within days), so the two modules can disagree, as cobra's own
test suite already does. The kit's suite and the probe's tests would have to run on every bump of
either module, and the shell drives (not just syntax checks) would have to run too, because the
bug that bit in Phase B lived in a generated script no Go test sees.
