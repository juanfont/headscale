# Own the parser, keep cobra's scripts

Cobra still works for the new Headscale CLI, but it is no longer the best tool for the job that 001 leaves to a framework. Under 001 the framework only reads the command line and answers Tab. Help, docs, validation, error text, config and output are Headscale's own, and viper is gone (#3674 merged on 2026-11-11). For that narrow job the evidence points to a choice between two: **stay on cobra**, or **write a small parser of Headscale's own and answer Tab through cobra's completion protocol, with cobra's shell scripts copied into the tree**. I recommend the second, in its "own grammar" form. It was the only adapter that passed all 155 required cases of the referee's second test kit as delivered. It did so in 228 lines, with no workaround lines, no new module and typed errors. Cobra reached the same 155 only after fixes. It carries about 42 lines that rely on behaviour cobra does not promise, it cannot refuse `-ojson` without a second tokenizer in front of it, and its own shell scripts have three bugs in real shells that Headscale cannot fix without waiting for a cobra release (the last one was 11.5 months ago). The own route has one real cost: Headscale keeps about 1,100 lines of copied shell in four languages working for years. Decision D21 already commits to a CI job that drives Tab in real bash, zsh and fish, and that job is what makes the cost bearable. Users see almost no difference either way. nixpkgs keeps `headscale completion bash|zsh|fish`, and the 128 integration-test calls change for the redesign, not for the parser. My confidence is moderate. The parsers separate clearly on behaviour and code shape, but the deciding cost is a judgement about how much shell the project is willing to own. That is the maintainer's call. On the referee's ranking, kong and creachadair/command tie behind the own parser, cobra comes next, and urfave/cli v3 comes last.

## The framework's job shrank to two things: argv and Tab

**001 cut the framework down to reading the command line and writing completion scripts.** The section "Our layer, not the framework's" says that one adapter file turns the tree of specs into framework commands, and that nothing else imports the framework ([001 L2132–2139](/home/kradalby/worktrees/headscale/cli-restructure-proposal/docs/proposals/001-cli.md)). An *adapter* here means that one file. A *spec* is a `command.Spec[In, Out]`: plain data with one input struct for arguments and flags. So a framework that wants to own help, errors, environment variables or config is a cost, not a gain. The brief told the researchers to give cobra no credit for being the incumbent, except for real migration cost and real user-visible compatibility ([BRIEF](../research_notes/Headscale%20CLI%20framework%20choice/BRIEF.md)).

**Today's use of cobra is shallow.** The CLI uses command literals, `RunE`, plain string, uint and bool flags, 28 aliases, a few persistent flags, `MarkFlagRequired`, `NoArgs`, and the help and completion commands that cobra adds by default. It uses no completion functions, no templates and no custom flag types ([current-usage](../research_notes/Headscale%20CLI%20framework%20choice/current-usage.md)). **Viper never saw a flag.** No `BindPFlag` exists anywhere, and the only link was `AutomaticEnv` in the config loader, which #3674 removed ([#3674](https://github.com/juanfont/headscale/pull/3674)). Cobra plus pflag is about 212 KB of a 79 MB binary, so size does not decide anything.

**Three outside parties depend on the command-line syntax.** nixpkgs runs `headscale completion bash`, `fish` and `zsh` at build time ([package.nix](https://github.com/NixOS/nixpkgs/blob/master/pkgs/by-name/he/headscale/package.nix)). The NixOS test kit is a public contract. 128 argv lists in 16 integration-test files call the binary. Every finalist can keep `headscale completion <shell>` and the hidden `__complete` entry point that today's installed scripts call. *`__complete` is cobra's completion protocol*: at each Tab the shell script runs `headscale __complete <words…>`, and the binary prints one candidate per line and a final `:<number>` line of flags called *directives* (for example "no space after this word" or "do not offer file names"). The earlier move to creachadair/command (#2647) was closed with the words "abandon for now" and no review. It mixed a framework swap with renames, a table layer and proto changes, and it lost shell completion. No technical objection to any framework is on record ([#2647](https://github.com/juanfont/headscale/pull/2647)).

**Five more rules follow from 001 as written, and were fixed without a question.** A usage error exits 1 (L653–654 know only 0 and 1). There are no flag abbreviations (`--exp` for `--expiry`), because 001 "never guesses". There are no stub commands for old names. `--` ends the flags and the words after it are positionals. Flags and positionals may be mixed in any order, because 001's own examples depend on it. Together these close G04, G05, G09, G20 and G22.

## Five finalists parse; the shell scripts separate them

**About 45 projects were screened and five were carried forward.** The knockouts were: no release or real commit for 24 months with no successor, no three-level nesting, a licence that does not fit BSD-3-Clause, or no way to build the tree from runtime data ([BRIEF](../research_notes/Headscale%20CLI%20framework%20choice/BRIEF.md)). The screen found no new framework worth deep research, but it found one *approach*. Tailscale copied cobra's four shell scripts into `tempfork/spf13/cobra` in 2024 and answers cobra's `__complete` protocol from its own `ffcli` tree ([tempfork](https://github.com/tailscale/tailscale/tree/main/tempfork/spf13/cobra), [commit 82394de](https://github.com/tailscale/tailscale/commit/82394debb7e8eb582c31fc1cc4c80869bd502a31)). That approach is what turned "a parser of our own" into a real finalist ([discovery](../research_notes/Headscale%20CLI%20framework%20choice/discovery.md)).

**Cobra is still near-universal among large Go CLIs.** kubectl, gh, docker, helm, podman, hugo, restic, rclone, NetBird, Netmaker, Zitadel and Cilium all pin cobra v1.10.2 ([discovery](../research_notes/Headscale%20CLI%20framework%20choice/discovery.md)). Tailscale's copied scripts have never been re-synced, and three completion issues there have no maintainer reply ([deep-own](../research_notes/Headscale%20CLI%20framework%20choice/deep-own.md)).

### How they were tested

**Each finalist had a champion who wrote one adapter against a shared test kit.** The kit holds a cut-down version of 001's command layer and 12 leaves from 001's tree ([spike-kit](../research_notes/Headscale%20CLI%20framework%20choice/spike-kit.md)). Its builder, not the framework, refuses misplaced flags, repeats and wrong argument counts. That keeps frameworks with inherited flags and frameworks with per-level flags on equal terms. All six adapters (two for "own": one with its own grammar, one with pflag underneath) passed all 112 required cases of the first kit. That told nothing apart. **The referee, who had no candidate, then built kit v2 with 43 more required cases and drove every binary through real interactive bash, zsh and fish in a pseudo-terminal, plus PowerShell's `TabExpansion2`** ([referee](../research_notes/Headscale%20CLI%20framework%20choice/referee.md)). Champions reported their own numbers; where the referee measured something differently, the referee's number is used below. The referee found no special-casing of test cases in any adapter. It did find that the first kit overrated urfave: urfave's in-process completion said "offer files" for every empty answer, which a real fish shell does not do.

Tab latency was 2.1–4.8 ms per `__complete` call for all six, so speed decides nothing. All six pass `-race -count=3`.

**kong** ends at 155 and 12/12, but needed the most fixing. Its tree must be built by generating Go struct types with `reflect.StructOf`, because kong has no API to add nested commands from data. Its errors are classified by where kong's trace stopped. One latent panic was found in the adapter: kong fills its targets only after `Apply`. Completion is not in kong at all ([#43](https://github.com/alecthomas/kong/issues/43), open since 2019). One person merges and tags everything, and his previous parser, kingpin, ended as "contributions only" ([deep-kong](../research_notes/Headscale%20CLI%20framework%20choice/deep-kong.md)). **creachadair/command** is already in go.mod and needed 4 fix lines. It reads error kinds from four message texts, accepts `-output` and `--o` as second spellings, and its root takes `-h`, `-o` and `-c` anywhere on the line, even as another flag's value. 210 of its 211 commits are by one person, and no issue has ever been filed against it ([deep-creachadair](../research_notes/Headscale%20CLI%20framework%20choice/deep-creachadair.md)). **urfave/cli v3** parses well, but its scripts never send the word under the cursor unless it starts with `-`, have no directives, and fall back to file names everywhere in bash and never in fish. Meeting D16 and the file rules meant replacing its completion, after which urfave is only a parser whose errors are untyped strings ([deep-urfave](../research_notes/Headscale%20CLI%20framework%20choice/deep-urfave.md)). The bash-completion maintainer and lefthook both report that completion got worse after moving to urfave ([bash-completion#1718](https://github.com/scop/bash-completion/issues/1718), [lefthook#1230](https://github.com/evilmartians/lefthook/pull/1230)). A v4 rewrite of urfave is planned ([#2192](https://github.com/urfave/cli/issues/2192)).

**Two cases the first kit missed changed the picture.** Kit v2 required that Tab offers only real command names (D16). Every framework adapter failed this, because D16 came after they were written. Each fixed it in 4–5 lines, except urfave, whose scripts do not send enough to decide it. Real shells then showed that **the `--flag=value` form was broken in four of six delivered adapters while every kit row was green** (cobra in fish, urfave, kong, creachadair). The kit drives completion in Go; only a real shell sees the script. That is the strongest argument for D21.

## The real choice: cobra's parser or ours, both with cobra's scripts

**Every finalist that does completion well ends up on cobra's protocol and cobra's scripts.** kong, creachadair and the fixed urfave borrow Tailscale's copy. The own adapters copy cobra's current scripts. Cobra generates them. So the question is not "cobra or not" for completion. It is who parses argv, and who keeps the scripts. kong and creachadair rank above cobra on behaviour, but they are not the real alternative. Each borrows the same scripts as the own route, adds a parser that the adapter must partly work around (generated struct types for kong, message-text errors and a `--` rule for creachadair), and has one person who can release. Against the own parser they lose on every count the referee measured. Against cobra they cost the same migration as the own parser and buy less. That leaves two honest options.

### The case for staying on cobra, at its strongest

**Zero user-visible migration and nothing new to own.** pflag's grammar is today's grammar, and the generated script bytes stay the same, so nixpkgs and every saved script behave as before. No module is added. The only version change is pflag v1.0.10 → v1.1.0, which the adapter needs for `PassUnknownFlagToArgs` and which gh already ships ([deep-cobra](../research_notes/Headscale%20CLI%20framework%20choice/deep-cobra.md)). **The parser behind `nodes delete --force` is the one kubectl, gh and docker use.** Its edge cases have met millions of users. With an own parser, the safety of a destructive command rests on Headscale's table tests alone. The own champion said so plainly: "the safety is in the tests, not in a library's user base". **The fixes to reach every required case were 13 lines of ordinary cobra API**, not workarounds. **Cobra keeps 1,143 lines of shell in four languages out of Headscale's tree.** Nobody on the project writes fish or PowerShell daily, and the CLI has one maintainer. Tailscale's copy shows what happens to an owned copy by default: frozen, with issues nobody answers. **And the choice can wait.** The adapter is one file. Leaving cobra later costs the same as leaving now, and the kit and shell harness that this research built would prove the replacement.

### The case for the own parser, at its strongest

**It is the only adapter that did exactly what was decided, as delivered.** 155/155 required, 12/12 stretch, 228 lines and no workaround. Each decided rule (D3, D6, D8, D9, D11, D15, D19, D20) is a line written, not a default switched off. `-ojson` is refused because nobody wrote it. There is no `help` command because nobody wrote one. Errors carry `{Path, Flag}` as Go types.

**Cobra's adapter leans on things cobra does not promise.** The referee counted about 42 such lines ([referee](../research_notes/Headscale%20CLI%20framework%20choice/referee.md)), and the cobra champion listed them himself ([deep-cobra](../research_notes/Headscale%20CLI%20framework%20choice/deep-cobra.md)):

| Cobra workaround                                                               | Why                                                                                                                                                            |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An empty-named, hidden help command                                            | Cobra adds a `help` command on every run and it cannot be removed (D8)                                                                                         |
| Groups made runnable, with `PassUnknownFlagToArgs`, and their args split again | Otherwise `nodes bogus` prints help and exits 0, and "unknown command" is only a string (D4)                                                                   |
| A counting flag value instead of an error in `Set`                             | `__complete` parses the same flags twice ([#2527](https://github.com/spf13/cobra/issues/2527), fix PR open)                                                    |
| A flag `Value` whose `String()` looks like a bool                              | Cobra reads `help` back with `GetBool` and prints to stdout otherwise                                                                                          |
| An argv rewrite on the Tab path (`--sort -la` → `--sort=-la`)                  | Cobra treats a dash-leading value as a flag name ([#2243](https://github.com/spf13/cobra/issues/2243))                                                         |
| D11 refusals not done                                                          | pflag has no switch for attached short values; refusing them needs a second tokenizer in front of pflag (the own-pflag adapter carries exactly that, 13 lines) |

The open fix PRs that would remove some of these (#2529, #2535, #2459, #2574) would also change the very behaviour the adapter relies on. They would land together, after a long gap, reviewed by one person. **Cobra's last release was v1.10.2 on 2025-12-04**, and in the following year about ten commits were merged, mostly by one maintainer ([releases](https://github.com/spf13/cobra/releases), [MAINTAINERS](https://github.com/spf13/cobra/blob/main/MAINTAINERS)). Cobra's own test suite fails three text tests with pflag v1.1.0, and cobra has no PR that adopts it.

**On the scripts, owning them is the only way to fix them.** The bugs in the next section hit cobra's adapter and the own adapters the same way, because both use cobra's current scripts. The own route already fixed the fish bug with a one-line patch. The cobra route waits for upstream: cobra's own fish quoting fix (61968e8) has sat unreleased since 2025-12-10. **The cost the cobra case leans on most, testing scripts nobody reads, is already paid by D21.** The referee's harness that found every completion defect is about 270 lines of Python and shell, runs in nix shells in under two minutes, and would become that CI job. The scripts themselves changed rarely: one or two user-visible fixes a year for bash, zsh and fish since 2023, so a re-sync is a diff of four templates.

**Migration is the same as cobra's for users.** The own route keeps `headscale completion <shell>`, the `__complete` and `__completeNoDesc` names and cobra's output shape, so nixpkgs' build step and scripts saved from today's build keep working. The integration tests use only spaced or `=` forms, and those parse the same. What users lose (`-ojson`, grouped shorts, leaf flags placed before the leaf such as `nodes --force delete 12`) is each a changelog line, and D11 asked for the first.

### Recommendation, confidence, and what would change it

**Recommendation: own grammar, own dispatcher, cobra's four scripts copied from cobra main with marked patches and cobra's Apache-2.0 licence next to them, and D21's shell job in CI from day one.** If the maintainer wants a tokenizer that thousands of programs use, own-pflag behaves identically on every case. It costs 26 more lines, 16 of which turn pflag features off.

**Confidence is moderate.** The measurements are solid and reproducible on the kit's tree. Nobody disputes the ranking on behaviour. What the evidence cannot settle is whether the project will keep a shell CI job alive and read cobra's script diffs once a release. The own champion put it this way: if that job exists, the scripts are "a small, quiet component"; if it does not, they become Tailscale's frozen copy.

**What would change the answer.** If the maintainer will not own the scripts or the shell job, stay on cobra and accept the fish error on `--columns=id,na`, plus the comma escaping, until upstream fixes them. If cobra quickly merges and releases fixes for the bugs below, most of the script argument goes away. A middle route also exists: the own parser with Tailscale's tempfork scripts imported instead of copied. That means zero shell lines owned, no new module, and older scripts that do not have the bash colon+comma bug. It also means scripts frozen at cobra's 2024-02 state, missing four later fixes, inside a package that is not a public API of `tailscale.com` and can disappear in any bump ([deep-own](../research_notes/Headscale%20CLI%20framework%20choice/deep-own.md)). Finally, a full tree of about 60 commands could surface parser cases the 12-leaf kit does not have. I expect that to cost table rows, not a change of verdict.

**Man pages do not move the choice.** D12–D14 put a roff writer of Headscale's own next to the reference generator. That writer is an estimated 150–250 lines with no new module. Cobra's `doc` package would pull md2man and the unmaintained blackfriday into go.mod, and it reads cobra's tree, not the specs ([man-pages](../research_notes/Headscale%20CLI%20framework%20choice/man-pages.md)).

## Cobra's own scripts carry three unreported bugs

**None of these has been reported anywhere.** The referee reproduced the cobra ones with a 50-line stock cobra program and no adapter, pinned to Headscale's versions (cobra v1.10.2, pflag v1.0.10), and again against cobra main at `adbc881` (`spikes/v2/stock-cobra/main.go` in the notes folder). The tools were bash 5.3 with bash-completion 2.17, zsh 5.9.1, fish 4.9.3 and PowerShell 7.6.5. A search of cobra's tracker for the fish bug found nothing ([deep-own](../research_notes/Headscale%20CLI%20framework%20choice/deep-own.md)).

The shared reproduction program:

```go
package main

import (
	"os"
	"strings"

	"github.com/spf13/cobra"
)

func values(vals []string) cobra.CompletionFunc {
	return func(_ *cobra.Command, _ []string, toComplete string) ([]cobra.Completion, cobra.ShellCompDirective) {
		head, cur := "", toComplete
		if i := strings.LastIndex(toComplete, ","); i >= 0 {
			head, cur = toComplete[:i+1], toComplete[i+1:]
		}
		sign := ""
		if cur != "" && (cur[0] == '-' || cur[0] == '+') {
			sign, cur = cur[:1], cur[1:]
		}
		var out []cobra.Completion
		for _, v := range vals {
			if strings.HasPrefix(v, cur) {
				out = append(out, head+sign+v)
			}
		}
		return out, cobra.ShellCompDirectiveNoFileComp | cobra.ShellCompDirectiveNoSpace
	}
}

func main() {
	root := &cobra.Command{Use: "headscale"}
	nodes := &cobra.Command{Use: "nodes"}
	list := &cobra.Command{Use: "list", Run: func(*cobra.Command, []string) {}}
	list.Flags().String("columns", "", "")
	list.Flags().String("sort", "", "")
	list.Flags().String("tags", "", "")
	_ = list.RegisterFlagCompletionFunc("columns", values([]string{"id", "name", "last-seen"}))
	_ = list.RegisterFlagCompletionFunc("sort", values([]string{"id", "name", "last-seen"}))
	_ = list.RegisterFlagCompletionFunc("tags", values([]string{"tag:ci", "tag:prod"}))
	nodes.AddCommand(list)
	root.AddCommand(nodes)
	if err := root.Execute(); err != nil {
		os.Exit(1)
	}
}
```

**1. fish: a single no-space candidate that starts with `-` breaks the script.** Build the program as `headscale`, then in fish 4.9.3 run `headscale completion fish | source; complete -C 'headscale nodes list --columns=id,na'`. The terminal shows `string split: --columns=id,name: unknown option` with a stack trace, and nothing completes. `--sort=-la` does the same. The cause is `string split --max 1 \t $__headscale_comp_results[1]` in [fish_completions.go](https://github.com/spf13/cobra/blob/main/fish_completions.go) (line 223), which has no `--`. That line was last touched in 2021. The fix is `string split --max 1 -- \t …`. It is reproduced on v1.10.2 and on main. Any cobra program that completes `--flag=<value>` with NoSpace in fish hits it.

**2. bash: a value with a colon and a comma is completed to a wrong value.** In interactive bash 5.3 with bash-completion 2.17, after `source <(headscale completion bash)`, type `headscale nodes list --tags tag:ci,tag:p` and press Tab. The line becomes `headscale nodes list --tags tag:ci,tag:tag:ci\,tag:prod`. That is a wrong value, not a cosmetic one. `tag:p` alone completes correctly. It is reproduced on v1.10.2 and main. Tailscale's 2024 copy of the script does not do it, which points at the 2025 escaping change in [bash_completionsV2.go](https://github.com/spf13/cobra/blob/main/bash_completionsV2.go) (commit 09d5664, in v1.9.0). That is an inference; nobody bisected it. Headscale's own `--tags` lists would hit it under cobra and under a straight copy of cobra's script. A fix was not attempted.

**3. bash: commas are escaped on the line.** Same setup, `headscale nodes list --columns id,na<Tab>` gives `id\,name`. The command runs correctly as `id,name`, but it looks wrong to the user. Cause: `printf %q` escapes `,`, also from commit 09d5664. Low severity.

**Also seen, possibly already known.** Cobra's PowerShell script throws on any empty answer with the NoFileComp directive and on a value ending in `,` (PowerShell's array operator). The empty-answer case overlaps cobra [#2481](https://github.com/spf13/cobra/issues/2481). Nobody checked whether the comma case is reported, and only `TabExpansion2` was run, not an interactive console. In pflag v1.1.0, parsing `nodes delete -ø` (a short flag that is not defined) returns a NotExistError whose name is the mojibake `-Ã`, because the shorthand is sliced by byte, not by character ([deep-own](../research_notes/Headscale%20CLI%20framework%20choice/deep-own.md)). Nobody searched pflag's tracker for it. In urfave/cli v3.14.0, the argv `nodes delete -5 --force` silently stops flag parsing (args become `["-5","--force"]` and force is not set), and a positional `" --force"` with a leading space is read as the flag `--force` because the word is trimmed before it is classified. The urfave champion found neither reported ([deep-urfave](../research_notes/Headscale%20CLI%20framework%20choice/deep-urfave.md)). Behaviour on urfave main is changing for `-5`.

**Known and already reported upstream (nothing to file).** Cobra: [#2527](https://github.com/spf13/cobra/issues/2527) double parse in `__complete`, [#2243](https://github.com/spf13/cobra/issues/2243) dash-leading values, [#1629](https://github.com/spf13/cobra/issues/1629) `-oj<Tab>`, [#2309](https://github.com/spf13/cobra/issues/2309) `=` inside values, [#1852](https://github.com/spf13/cobra/issues/1852) aliases not completed. kong: [#570](https://github.com/alecthomas/kong/issues/570) `-o=json` gives `=json`, and upstream will not change it. urfave: per-flag completion [#1905](https://github.com/urfave/cli/issues/1905) was closed unimplemented. creachadair/command's `--` rule (it stops flags only at the level where `--` is the first free word) is tested on purpose and is by design, not a bug.

## What nobody measured

**PowerShell was only driven through `TabExpansion2`.** What an interactive console shows when the script throws is unknown. **Completion descriptions were never seen**, because the kit's tree has no help text. The mechanism exists in cobra's protocol (`word\tdescription`). **macOS bash 3.2 without bash-completion, Windows, zsh menu-select styles and zsh frameworks such as oh-my-zsh were not tested.** **Every number is on the kit's 12 leaves and 9 groups**, not on 001's real tree of about 60 commands with real specs. **Upgrade behaviour over time was not measured.** The "unpromised behaviour" lists say where an adapter would break on a framework bump, not that it will.

**Nobody fixed the bash colon+comma corruption** in a copied script, so its cost is unknown. **Nobody drove a script saved from today's cobra-built Headscale against a new own-parser binary.** The claim that saved scripts keep working rests on the protocol being the same, not on a test. **The referee's shell harness has not run in GitHub's CI**, only in local nix shells, so the "under two minutes" figure is local. **Live-name completion (R62) was built by nobody**. Every finalist has a hook for it, but none was exercised. **Kong's and pflag v1.1.0's size in the real Headscale binary were not measured.** Both are expected to be small next to the measured ~212 KB of cobra and pflag in a 79 MB binary.

For man pages, the writer's size (150–250 lines) and the rendered length of one page (about 1,500 lines) are estimates. Whether nfpm compresses man pages, whether pagers follow `.MR` links, and how the FreeBSD port packages the page are unverified ([man-pages](../research_notes/Headscale%20CLI%20framework%20choice/man-pages.md)). **Why #2647 was closed is not on record**, and only its author knows. **Whether distributions other than nixpkgs call `headscale completion`** (Arch, Homebrew, Alpine, Debian) is unverified. Homebrew's `headscale-cli` formula does generate completions from the binary.

## Conclusion

Under 001, the framework's value is no longer its parser. All six adapters, two of them Headscale's own, reached every required case on the kit after small fixes. The value is in who answers Tab and who can fix the scripts that ask. Cobra's real advantage is that it spares Headscale those scripts. Its real weakness is that it then makes Headscale wait for them, and the three bugs found here show the wait is not hypothetical. D21 changes the balance more than any other decision. Once CI drives Tab in real shells, owning the scripts stops being a blind risk and becomes a maintained component, and from there a 228-line parser that does only what was decided is the better tool.

Whatever the choice, three things should happen anyway. First, report the fish `string split --` bug and the bash colon+comma corruption to cobra; both hit Headscale today on any route that uses cobra's current scripts. Second, keep kit v2 and the referee's shell harness as the adapter's permanent tests, so the next framework question is answered by running them rather than by another round of research. Third, update 001: rewrite the cobra-specific sentences (L2134–2139, L3262), mark the config-stack PRs merged, and work D1–D22 into the sections listed above.
