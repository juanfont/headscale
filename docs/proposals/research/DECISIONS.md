Facts fixed without a question (they follow from 001 as written):

- Exit code of a usage error is 1 (001 has only 0 and 1).
- No flag abbreviations (`--exp` for `--expiry`): 001 "never guesses".
- No stub commands for old commands (decision log of 001); see D5 for the hint table.
- `--` ends the flags; the words after it are positionals (POSIX).
- Flags and positionals may be mixed in any order (examples in 001 depend on it).
- Viper is gone: juanfont/headscale#3674 merged 2026-11-11. No framework config or env binding is wanted.
- An empty list value is always an error and never means "clear" (001, "Lists as input"); this covers `--tags=` and `--filter=`.
- A flag of a leaf may not stand before the subcommand; only `-c` and `-o` may (D3).
- `-output`, `--o`, `-help`, `--h` are unknown flags: one spelling per flag.
- No command in the tree takes a variable number of arguments, so `...` goes out of the `ArgCount` row (closes C8) and the library has no variadic positionals.
- pflag is not the flag reader and not a standing test oracle: the differential test against it would have caught none of the bugs found.

Calls made by the assistant, not asked (small; each can be reversed):

- The library's Tab callback gets the parsed line so far, not only the typed prefix. Live names from the server (R62 in requirements.md) need the `-c` value from the line, and a later change would break every caller.
- `--version` together with other words (`--version nodes list`) is a usage error; `--` where a command word is expected is an unknown command.
- Tab keeps completing after `-h`; no Tab values for bools (`--force=<Tab>`); grouped short flags (`-vv`) stay refused.
- Corpus upkeep: one look per year at new upstream tests and bug reports.
- The library's name is the maintainer's to choose at implementation time (working name `cmdline`).

Second set of calls by the assistant (2026-11-17, from the open questions of the 001 draft and of `rules.md`; none confirmed by the maintainer):

- 001 Q2: confirmed by the maintainer, see D38.
- 001 Q3: `ReadsConfig` is also true for `version` (it reads `disable_check_updates`) and `check all` (it has a default file). This follows from "every command that reads the config takes `--config`".
- 001 Q4: `-h` may stand before the subcommand, like `-c` and `-o` (`headscale -h nodes list` is the help of `nodes list`; all six test adapters and today's CLI do this).
- 001 Q5: the flag block of the help keeps its layout as Headscale's own and lists `-c` and `-h` too. No new help design.
- 001 Q6: a positional that is a file (`policy set <file>`, `check config [file]`) is marked like a path flag and Tab offers files (D27 extended; cobra does this today).
- 001 Q9: `--help`, `--version` and `--list-columns` leave before the API client is made; the builder list gets a step for it.
- 001 Q10: `Ctx` carries stdin, stdout, stderr, the environment and an is-terminal switch; a test builds a fresh tree per case and cases run in parallel.
- 001 Q11: the man page is written by `headscale generate man`, the same pattern as `headscale generate cli-reference`; the file is committed and diffed in CI (D14).
- Library: a `Check(root) error` function refuses a tree with two children of one name, one spelling for two flags, or a bad flag name. Headscale runs it in a test.
- Library: a `+` or `-` sign is completed only on lists that take signs (`--columns`, `--sort`); that logic is Headscale's.
- Layer: an empty item inside a list (`a,,b`) and an empty `-o=` are bad values.
- Library: no compatibility promise while it lives in Headscale's repository; the promise is written when it moves out (D25).
- All other "rules that nobody decided" in `rules.md` stay as the consolidated build does them (a flag word is any word of two or more bytes that starts with `-`; names are compared byte for byte; `--help=false` runs the command; flags may stand between group words; short flags are ASCII).

Third set of calls by the assistant (2026-11-18, from the open questions of the 003 draft; none confirmed by the maintainer; all listed in 003 under "Calls not confirmed by the maintainer"):

- The library itself refuses `-ojson` and grouped short flags, and its tests hold that, because a complete specification must be exact. Headscale's promise to users stays "not promised" (D11).
- The detail of D35 (where each kind of mistake sits on the line) is Headscale's policy and is in 001; 003 has only the mechanism.
- `Check` also refuses a help text with a line break and a root command named `__complete`.
- The real-shell job runs on every pull request that changes `go.mod` or the CLI.
- The corpus rows get a library expectation and a caller expectation when the library is built; the split of the 485 rows is implementation work.
- A Completer that calls a server (time limit, failure) is specified when the first one is built.
- `headscale --version nodes list` is an unknown flag of `nodes list` (only `-c`, `-o` and `-h` may stand before the subcommand), so the approved sentence "--version takes no command and no other flag" became "--version takes no other flag", shown for `headscale -c x --version`. This changes one sentence that the maintainer approved in D38; he must see it.

Fourth set of calls by the assistant (2026-11-18, made while building the typed library, `spikes/final-typed`; none confirmed by the maintainer; each is in `typed-library.md` with the alternative, and marked `call 4` in `rules-typed.md`):

- Flags outside the input struct are structs too, listed in `Flags` of a command or a group and read with `cmdline.Get[T](line)`. Confirmed since: D48.
- `Line.Flags` and `Line.Args` keep the text as typed and the positions, for the caller's own mistakes (D35) and for Tab. D41 says no strings; see "Conflicts", A.
- `Reader` and `LateReader` are options of `cmdline.New`; there is no package-level registry. A late reader takes the client from the context of `Line.Run`.
- A named type must say how it is read; only Go's own basic types are read by the library. Numbers are decimal.
- Defaults are a `default` tag.
- The late readers run inside `Line.Run`; there is no separate step.
- `--output` was checked for "empty" when read and for "json" later, so that the examples of D35 with `-o a -o b` stood. Decided the other way since: D49, and the build follows it.
- A list never takes an empty word or item; no setting.
- `cmdline.New` is the check: it names every problem, and there is no separate `Check`.
- A tag key the library does not know is refused; in a group's scope a flag name belongs to one struct type.
- Tab asks the type of the field (`Complete` method); the commas of a list are the library's.
