# Man pages for the new Headscale CLI

Date: 2026-11-17. Evidence marked [local] = checked in the nix store / worktree on this machine, [gh] = GitHub API / raw file today, ESTIMATE / UNVERIFIED as stated.

## Recommendation (short)

- **Entry point: one page `headscale(1)` that holds the whole tree**, generated by Headscale's own walker over the specs. `man headscale` is the only name anyone types; `/nodes routes set` in the pager finds a command.
- **Format: direct roff `man(7)` written from Go** (about 150-250 lines, no new dependency), checked in CI with `mandoc -T lint -W warning`.
- **Shipping: commit the generated `headscale.1` next to `docs/ref/cli.md`, diff-checked by the same CI step; goreleaser and nixpkgs install the committed file.** No binary run needed at package time, so cross builds are safe.
- **Runner-up: middle way** (top `headscale(1)` with full tree and a synopsis per command, plus one page per top-level group, about 10 pages). Take it if the single page proves unreadable (see the length table). Same walker, same writer; the cost is about 10 files to install and a SEE ALSO that has to be right.
- Not recommended now: per-command pages (60 + groups), mdoc, any Markdown-to-roff library. `headscale.yaml(5)` and a section-8 page are a separate, later decision.

### One source for `--help` and the man text

Yes. The spec already carries `Use`, `Short`, `Long`, `Example`, flags and aliases (001, "What every command must carry"). The man writer is a third renderer next to the help and the Markdown reference; it must read the same fields and add nothing of its own, except the fixed front matter (NAME, DESCRIPTION of the whole tool, FILES, EXIT STATUS, ENVIRONMENT). The tree-walk test in 001 ("a command has an empty Short, Long or Example") already guards the inputs. Two traps:

- `Long`/`Example` contain console text and backticks written for a terminal. The writer must treat them as literal text (no Markdown pass), or apply the same minimal rules as the help renderer: indented lines become no-fill examples, blank line = paragraph.
- Anything the help adds at render time (the "Server commands take -o json" footer, column table, truncation note) must come from the same function, not be re-typed for man.

### Escaping traps (groff and mandoc)

| Trap                                          | Rule                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backslash                                     | `\` -> `\e` (or `\\`); required in examples with regexes and Windows paths                                                                                                                                                                                                                           |
| Hyphen vs minus                               | In UTF-8 output groff >= 1.23 turns `-` into U+2010 hyphen; an option such as `--expiry` pasted from the page then contains a Unicode hyphen. Write `\-` for every `-` that is part of an option, a path or a command. Plain `-` only in prose compound words. `.nh` (as gh sets) stops hyphenation. |
| Leading `.` or `'` at line start              | roff reads it as a request. Prefix with `\&` on every output line (example text, flag descriptions, wrapped lines).                                                                                                                                                                                  |
| `"` in macro arguments (`.TH`, `.SH`, `.TP`)  | quote the argument; double `""` or avoid                                                                                                                                                                                                                                                             |
| Unicode                                       | UTF-8 passes in groff >= 1.23 and mandoc, but `man` on older systems with `LANG=C` drops or garbles; keep ASCII, use `\[u2192]` or avoid arrows. gh/cobra output uses `\[la]` `\[ra]` (md2man link markers).                                                                                         |
| Long unbreakable text (URLs, long flag names) | `\:` break hints; `.nf`/`.fi` for example blocks so lines are not filled; `.EX/.EE` exist in groff and mandoc 1.14.x but `.nf` is safe everywhere                                                                                                                                                    |
| Empty line in the middle of a `.TP` body      | produces a blank paragraph; use `.IP`/`.PP` explicitly, or `.sp`                                                                                                                                                                                                                                     |
| `.TH` date and source                         | mandoc warns on an unparsable date (observed: `cannot parse date, using it verbatim: TH Oct 2026` on gh's page); use `YYYY-MM-DD` or `Month D, YYYY`                                                                                                                                                 |
| Tables                                        | `tbl` is a preprocessor; man-db runs it, mandoc supports it, but avoid: list options as `.TP` entries                                                                                                                                                                                                |

Recommendation: committed + CI-diffed, because 001 already commits `docs/ref/cli.md` the same way, and nixpkgs (the channel that already needs the guard) then needs no binary. Keep a `headscale generate man` command anyway: it is the generator the CI check and anyone regenerating call; same pattern as `generate cli-reference`. Keep generated files in their own commit (001 rule).

## Open questions for the maintainer

1. **Layout of the pages.**
    - A: one page `headscale(1)` with everything. Cost: simplest generator and packaging; `apropos nodes routes` finds nothing; one long page (about 1500 rendered lines, ESTIMATE).
    - B: `headscale(1)` + one page per group (`headscale-nodes(1)`, about 10 pages). Cost: about 10 files to ship and keep consistent; users who read only the root page miss details; SEE ALSO is plain text, so users retype names.
1. **Generated at build or committed.**
    - A: committed `docs/ref/headscale.1`, CI diff. Cost: one more file in the stale-check, and `.TH` carries no version or date (or a fixed string).
    - B: generated in goreleaser hook / nixpkgs `postInstall`. Cost: nixpkgs needs the `canExecute` guard or an emulator (caddy does the latter); man page missing in cross builds without it; correct version in header.
1. **`headscale.yaml(5)` and `headscale(8)`.**
    - A: ship only `headscale(1)` now. Cost: none; config reference stays on the docs site.
    - B: also generate `headscale.yaml(5)` from the config schema (#3680). Cost: a fourth renderer over the schema plus a CI check; the page is most useful to the people who install the deb.
1. **Writer.**
    - A: direct roff man(7) from Go (recommended). Cost: about 150-250 lines to own, with escaping rules we must get right and test.
    - B: `muesli/mango` + `roff`. Cost: two small modules, last tag 2022; saves maybe 100 lines but still needs the same escaping tests.
1. **`.TH` date and version in a committed page.**
    - A: omit (or fixed `"headscale"`), check that `mandoc -T lint` accepts it. Cost: reader cannot tell which version the page is for.
    - B: render version and date at release into a copy used for packages; the committed copy stays neutral. Cost: a second, non-checked artifact.
